## 2) TODAY'S RPC CHANGES — race / thrash / livelock review

### getLogs softban recovery (f05b227 + e9cf4c6) — SOUND, minor residue
- `pool.py:181-214` `probe_eligible_endpoints` excludes hard-bans + fresh capability exclusions; soft-bans stay eligible. `pool.py:92-119` `pool_fully_down` no longer counts soft-bans; `pool_rate_limited` (`:122-144`) keeps the crawl alive. The base/celo deadlock class is genuinely closed.
- 300s cap (`ban_state.py:27` `_RATE_LIMIT_STREAK_BAN_CAP_S = 300`): cannot starve — an all-soft-banned pool still dials via `least_banned_endpoint` fallthrough (`pool.py:353-363`) and the rate-limited crawl (`transfer_handler.py:172-190`).
- **P2 — streak never decays on ban expiry:** `ban_state.py:142-145` lazy expiry pops `_endpoint_bans` but leaves `_endpoint_429_streaks` ≥3 and does not persist the clear. A provider that 429s once per hour is re-soft-banned for the full 300s on every single 429 forever (streak only clears on success, `:198-199`). Bounded (cap 300s) but permanently punitive. Fix: reset streak when the ban window elapses.
- **P2 — persistence is fail-silent:** `ban_state.py:48-49, 74-75` swallow cache_db import/IO errors with no log — a broken cache_db silently disables ban persistence and restarts re-hammer the pool (the exact incident the persistence was built to prevent). Log at warning once.

### Capability re-admission (82de272) — bounded, one gap
- `capabilities.py:313-334` reprobe due after 300s; `pool.py:211` stale exclusions re-enter the probe set. Re-probing is gated by `desperation_probe_due` → **not unbounded**.
- **P2 — fetch path never refreshes `probed_at`:** `set_logs_capability` is called only from `rpc/verify.py` (hourly verify). A stale-excluded endpoint that still refuses during a desperation probe gets no refreshed verdict, so it stays "stale" and is re-dialed every probe interval until the hourly verify pass rewrites the record. Bounded but wasteful; refresh `probed_at` (or re-classify) on the probe path.
- Normal rotation (`transfer_handler.py:111,396` + `chains/helpers.py:75-92`) does **not** filter capability-excluded endpoints — they are dialed every fetch cycle. Mitigated in practice by `apply_verified_endpoints` replacing the pool with the verified log set, but a chain that skips verification (startup fallback) dials structurally-refusing endpoints every cycle. [REVIEW]

## 8) NEW FINDINGS — ranked

### N-1 (P1, DATA-LOSS): backfill executor treats quota-deferred `[]` as "confirmed empty"
- `indexer/backfill_executor.py:65-76` — `logs = await host.rpc.get_logs(...)`; `get_logs` returns `[]` on quota-defer (`client.py:865-868`); `if not events: return True` → the backfill chunk is marked fully handled and dequeued **without any rows written**. RC-1's silent-empty shape now also permanently drops *backfill* ranges (reconciliation rewinds, stalled-chain backlog), not just live sync. Fix: make the defer path return `None` (its own documented failure shape) or have the executor distinguish "deferred" via `_defer_reason_for` before returning True.

### N-2 (P1, OBSERVABILITY): live `_guard_state_regression` copy lost the regression metric
- See §6 first bullet. The state-regression counter (`lite_indexer_state_regression_detected`) is dead code in the shadowed mixin copy; the live copy never increments it. Any dashboard/alert on that metric reads zero during real regressions.

### N-3 (P2): 429-streak never resets on soft-ban expiry (`ban_state.py:142-145`) — repeated single 429s keep a 300s ban alive indefinitely.
### N-4 (P2): ban persistence fails silently (`ban_state.py:48,74`) — persistence is the feature; its failure must be visible.
### N-5 (P2): stale capability exclusion never refreshed on the probe path (`capabilities.py:313-334` + no `set_logs_capability` caller outside verify) — bounded re-dial waste.
### N-6 (P2): split residue — dead `_noop` import, duplicate logger, private `__all__`, dead module-level `_REORG_SENTINEL`, dual structure gates (§3/§6).
